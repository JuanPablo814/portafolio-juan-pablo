Mala Fama Games: arquitectura, retos y resultados

Arquitectura

La tienda tiene tres capas. El navegador muestra páginas HTML, CSS y JavaScript. El servidor PHP genera las páginas y expone una API REST. La información vive en una base de datos MySQL.

  1. NavegadorCatálogo con buscador y filtros, carrito, cuenta de cliente y panel de administración.
  2. Servidor PHPPáginas, sesiones, reglas de negocio y API REST.
  3. Base de datos MySQLJuegos, inventario, pedidos, códigos digitales, clientes y puntos.

El repositorio separa el código en carpetas: api, css, js, includes, base de datos, docs e img.

Mi módulo

  • Cuentas de usuario y panel de cliente, con historial de pedidos y puntos.
  • Panel de administración con tablero, gráficas y reportes por fechas con descarga en CSV.
  • Páginas legales: términos, devoluciones y privacidad.

Retos técnicos

  • Cancelar sin dejar datos inconsistentes. Al cancelar un pedido, el sistema regresa el inventario, anula los códigos digitales y ajusta los puntos del cliente en un solo paso.
  • Pagos que parecen reales sin serlo. El pago es simulado: no cobra, no envía nada y no guarda datos de tarjeta. La tienda lo avisa al cliente.
  • Cuatro módulos en un solo repositorio. Coordinamos el trabajo con Git y GitHub Desktop, con commits por módulo.
